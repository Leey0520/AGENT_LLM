# 数数项目空间与看板操作标准

## 项目空间

基础布局按五类组织：基础数据（新增、活跃、留存、生命周期和画像）、玩法模式（参与、通关、时长）、其他系统（经济、商城等）、付费概览（收入、付费率、ARPU、ARPPU）和版本数据（版本渗透率等）。已上线项目新增版本看板，优先优化已有看板，不为每个小内容重复建一套。

看板设置：

- 打开多时区开关，通常使用 UTC+08:00；改变展示时区要记录大事件。
- 按项目需要配置账号 ID、设备码等分析主体；具体主体名称和去重字段放在项目页。
- 为大版本上线、停服、下架等事件增加日期标注，方便解释 DAU 和新增的拐点。
- 看板统一在下班后或凌晨定时更新，并以小时错开各看板；查询慢、数据量大的项目才开启近似计算。

## 标签和分群

- 看板依赖的条件标签、首末次标签、指标值标签和 SQL 标签打开自动更新，自动备份关闭，时区与项目保持一致。
- 各标签自动更新时间以 5 分钟错开，名称和描述必须说明主体。
- ID 标签/ID 分群、条件分群/SQL 分群都要明确分析主体；不要把账号主体和设备主体混在名称不清的分群里。

## 监控周期

- 常规监控：每周一上午、每周五下午。
- 版本上线第一周含周末值班；测试项目 B 轮及以后在上线当日监控；新项目上线前两周以及首周含周末监控。
- 核心数据至少看活跃、新增、留存、收入、付费率、ARPU、ARPPU、LTV，并拉长到 1 个月、3 个月、半年和一年观察趋势。
- 发现异常先在群内同步并约定 3～7 天内给出查验结果，再同步制作团队和 AM；涉及收入的看板只开放给核心数据组等授权人员。

## 权限

项目空间权限由 Chillyroom 账号管理，项目负责人作为协作者。制作组和运营组可查阅非付费基础/内容数据；核心数据组、AM 等按授权查看付费数据；非数据组分析师不开放项目空间协作权限。新增账号、成员权限和收入权限调整前，先由权限负责人评估。
