# 战魂铭人付费与首次付费口径

## 适用范围

本页定义战魂铭人的付费率、ARPU、ARPPU、首次付费、版本首次付费、商品类别付费和商品构成口径。线上字段、订单关系、币种、退款和金额结算语义仍须核验；本页不替代订单号级验收。

版本窗口不统一。每个指标必须分别声明版本自然周期、上线后前 N 日、上线后 30 日或其他观察窗口。

## 数据与主体

| 项 | 口径 |
| --- | --- |
| 事件 | `claim_order`、`order_finish` |
| 主体 | `#user_id` |
| 商品 | `#vp@combine_sku_name_item_name` |
| 商品类别 | `#vp@item_sku_name_type` |
| 金额 | `#vp@order_price_total` |
| 时间 | 服务端事件按 `DATE_ADD('hour', 8, "#event_time")` 转北京时间 |
| 订单边界 | 一笔订单只会落在 `claim_order` 或 `order_finish` 其中一个事件；按订单处理时不做 `order_finish` 优先的二次去重，仍须订单号级线上核验 |
| 缺失记录 | 迁移渠道付费记录自 2024-07-19 起才完整；更早历史不能当作完整全历史 |

`#user_id` 与 `#device_id` 没有通用映射规则。付费分子使用 `#user_id`、活跃分母使用 `#device_id` 时，必须标记为跨主体指标并说明限制。

## 付费率

| 指标 | 分子 | 分母 | 过滤与粒度 |
| --- | --- | --- | --- |
| 日付费率 | 当日至少一笔有效付费的去重 `#user_id` | 当日活跃的去重 `#user_id` | 日粒度；口径用于需要与付费主体一致的分析 |
| 版本付费率 | 版本窗口内至少一笔有效付费的去重 `#user_id` | 版本窗口内活跃的去重 `#user_id` | 版本窗口按分析目标声明；不是各日付费率的简单平均 |
| 商品类别付费率 | 版本窗口内购买该 `#vp@item_sku_name_type` 的去重 `#user_id` | 版本窗口内活跃的去重 `#user_id` | 同人可购买多个类别，各类别分子互不排斥，合计可大于总付费人数 |
| 商品类别付费率（首次付费机会人群分母） | 同上 | 首次付费机会人群 | 只有显式声明时才替换分母，不能与版本活跃分母混用 |

若活跃分母只能取 `#device_id`，则属于跨主体指标；不能把结果直接解释为同一批人的付费率。

分析「除启航礼包外的主要商品」时，应先用 `#vp@combine_sku_name_item_name = '启航礼包'` 排除该商品，再按商品类别聚合。不要因为启航礼包属于礼包类别而直接删除整个礼包类别。

## ARPU 与 ARPPU

| 指标 | 分子 | 分母 | 备注 |
| --- | --- | --- | --- |
| ARPU | 期间有效付费金额合计 | 同期活跃去重 `#user_id` | 主体统一为 `#user_id`；窗口按分析目标声明 |
| ARPPU | 期间有效付费金额合计 | 同期至少一笔有效付费的去重 `#user_id` | 付费主体同 `#user_id` |

按角色上线分析的示例窗口为角色上线后 30 日，但 30 日不是所有版本或所有指标的默认窗口。

`#vp@order_price_total` 的币种、原价/实付、折扣和退款冲减未锁定前，ARPU 与 ARPPU 只能作为当前字段口径结果，不得宣称已经得到最终实收。

## 首次付费

| 项 | 定义 |
| --- | --- |
| 首次付费 | 该 `#user_id` 在可见全历史中的第一笔有效付费，不是版本内第一笔 |
| 首次付费时点 | 按 `#event_time` 取最早一笔；服务端事件先转北京时间 |
| 首次付费机会人群 | 版本窗口内活跃，且版本开始日之前没有任何付费记录的去重 `#user_id` |
| 活跃侧来源 | `tap_start` 上携带的 `#user_id`；必须先验证登录后 `#user_id` 覆盖率 |
| 版本首次付费率 | 首次付费日期落在版本窗口、且属于首次付费机会人群的去重 `#user_id` ÷ 首次付费机会人群 |
| 商品首次付费率 | 在上述版本首次付费人数中，首付商品为该 SKU 的去重 `#user_id` ÷ 首次付费机会人群 |
| 商品占首次付费人数比例 | 首次付费商品为该 SKU 的去重 `#user_id` ÷ 版本内首次付费人数 |

一个 `#user_id` 的首次付费只归入一个 SKU。各商品首次付费率堆叠后合计等于版本首次付费率。

因为迁移渠道付费记录自 2024-07-19 起才完整，早期版本的「版本前无付费记录」可能把更早的真实付费者误判为首次付费机会人群。结果必须注明该限制。

## 商品金额

| 指标 | 分子 | 分母/粒度 | 备注 |
| --- | --- | --- | --- |
| 分 SKU 付费金额 | 指定窗口内该 `#vp@combine_sku_name_item_name` 对应的 `#vp@order_price_total` 合计 | SKU；可按日或版本聚合 | 金额语义未锁定前不得直接称为最终实收 |
| 版本日均付费金额 | 版本窗口内的有效付费金额合计 | 版本窗口的自然日天数 | 先汇总版本金额再除以已声明窗口天数，不是把每日金额再次平均 |
| 分 SKU 日均金额 | 该版本内各 SKU 金额合计 | 版本窗口自然日天数 | 堆积图每层为一个 SKU，其他 SKU 合并为「其他」 |

分 SKU 金额堆积图按每版本金额降序保留前 8 个 SKU，其余归「其他」。N 可按分析目标调整，但必须在图表口径中声明。

## 商品构成展示

- 分商品人数和金额构成默认按每版本购买人数或金额降序展示前 N 个 SKU，其余归「其他」并排在末位。
- 本会话使用的 N 包括 8、10、12；N 必须按分析目标声明，不能把某一次分析的上限写成全局固定值。
- 同一人购买多个 SKU 时，在分商品人数构成中可在多个商品下出现；需要在口径中明确这是购买人数而非互斥人数。
- 商品构成使用 `#vp@combine_sku_name_item_name`，商品类别使用 `#vp@item_sku_name_type`，两者不能混为同一层级。

## 展示精度

- 比率保留两位小数；先完成分子、分母聚合再四舍五入，不得先取整或先输出假小数。展示层即使第二位小数为 0 也要保留，例如 `16.50%`，不能写成 `16.5%` 或 `17%`。
- 金额精度按币种和底层字段确认，不在本页预先截断。

## 待确认项

- `claim_order`、`order_finish` 的订单号、订单状态和退款关联。
- `#vp@order_price_total` 的币种、实付、折扣、退款冲减和跨订单语义。
- `tap_start` 上 `#user_id` 的覆盖率，以及未登录活跃是否纳入分母。
- 首次付费使用可见表最早记录时，2024-07-19 前的缺失处理。
